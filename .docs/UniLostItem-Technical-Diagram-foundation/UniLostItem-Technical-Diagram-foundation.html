API Uç Noktaları

15 Endpoint — RESTful Design
API Surface — /api/v1/
📦 /api/v1/lost-items
GET / AllowAnonymous Aktif eşyaları listele (sayfalı, filtreli, sıralı)
GET /{id} AllowAnonymous Eşya detayını getir
POST / [Authorize] Yeni eşya oluştur (doğrudan Active)
PUT /{id} [Authorize] Owner Kendi eşyasını güncelle
DELETE /{id} [Authorize] Owner/Admin Eşyayı soft-delete ile sil
GET /my-items [Authorize] Kendi eşyalarımı listele
📋 /api/v1/claims
POST / [Authorize] Eşya üzerinde talep oluştur
GET /{id} [Authorize] Owner Talep detayını getir
GET /my-claims [Authorize] Kendi taleplerimi listele
PUT /{id}/cancel [Authorize] Claimant Talebi iptal et
GET /by-item/{lostItemId} [Authorize] Poster Eşyadaki talepleri listele
PUT /{id}/respond [Authorize] Poster Talebi onayla/reddet
PUT /{id}/extend [Authorize] Poster Talep süresini uzat (+2 gün, max 2x)
PUT /{id}/admin-review [Authorize] Admin Admin talep incelemesi
GET /pending [Authorize] Admin Bekleyen tüm talepleri listele
🔐 /api/v1/auth
POST /register AllowAnonymous Yeni kullanıcı kaydı
POST /login AllowAnonymous Kullanıcı girişi (JWT döner)
POST /refresh-token AllowAnonymous Access token yenile
GET /profile [Authorize] Mevcut kullanıcı profilini getir
PUT /profile [Authorize] Kullanıcı profilini güncelle

07

Kullanıcı Akışları

Senaryo Bazlı Kullanıcı Hikayeleri
S

Serhan Kayıp Eşya İlanı Verir

BaseUser — Eşya Sahibi
1
Kayıt Olur Serhan üniversite e-postasıyla sisteme kayıt olur. BaseUser rolü atanır. POST /auth/register
2
Giriş Yapar JWT access token alır. Token ileAuthenticated istekler yapar. POST /auth/login
3
Eşya İlanı Oluşturur Laptop'unu kaybettiğini bildirir. Kategori: Elektronik, Tip: Lost. Kampüs kütüphanesi konumu. POST /lost-items
4
Gelen Talepleri İnceler Birisi laptop bulduğunu iddia eder. Serhan talep detayını ve açıklamayı okur. GET /claims/by-item/{id}
5
Talebi Onaylar "Bu benim laptop! Seri numarası eşleşiyor" yorumuyla talebi onaylar. Eşya Resolved olur. PUT /claims/{id}/respond
A

Ahmet Bulduğu Eşyayı İade Eder

BaseUser — Eşya Bulucu / Talepçi
1
Arama Yapar Ahmet bir cüzdan bulur. Sistemde "Kayıp Cüzdan" ilanlarını filtreler. Konum: Yemekhane. GET /lost-items?category=CantaCuzdan&type=Lost
2
Eşya Detayını Görür Zeynep'in kaybettiği cüzdan ilanını bulur. Açıklama ve fotoğraf eşleşiyor. GET /lost-items/{id}
3
Kayıt Olur ve Giriş Yapar Talep oluşturmak için hesap açar ve JWT token alır. POST /auth/register → POST /auth/login
4
Talep Oluşturur "Mavi deri cüzdan, içinde 3 kart var. Yemekhane girişinde buldum" açıklamasıyla talep oluşturur. POST /claims
5
Talep Durumunu Takip Eder Zeynep 2 gün içinde yanıt vermez. Serhan (Admin) devreye girip talebi inceler. GET /claims/my-claims
Z

Zeynep Birden Fazla Talebi Yönetir

BaseUser — Eşya Sahibi (Çoklu Talep)
1
Found İlanı Verir Zeynep anahtar bulduğunu bildirir. Kategori: Anahtar, Tip: Found. Mühendislik fakültesi. POST /lost-items
2
3 Talep Gelir Ahmet, Serhan ve başka biri anahtar için talep oluşturur. GET /claims/by-item/{id}
3
Ahmet'in Talebini Reddeder "Anahtar modeli uyuşmuyor" yorumuyla reddeder. PUT /claims/{id}/respond
4
Serhan'ın Süresini Uzatır Serhan doğru kişi olabilir ama belge getirmesi lazım. Süreyi 2 gün uzatır. PUT /claims/{id}/extend
5
Serhan'ın Talebini Onaylar Serhan anahtar fotoğrafını getirir, eşleşiyor. Zeynep onaylar. PUT /claims/{id}/respond
S

Serhan Admin Olarak Müdahale Eder

Admin — Sistem Yöneticisi
1
Bekleyen Talepleri Görür Admin panelinde süresi dolan taleplerin listesini açar. GET /claims/pending
2
Talep Detayını İnceler Ahmet'in Zeynep'in cüzdanı için yaptığı talebi okur. Açıklama detaylı, eşleşme ihtimali yüksek. GET /claims/{id}
3
Admin Onayı Verir Zeynep 2 gün içinde yanıt vermediği için Serhan admin olarak talebi onaylar. Cüzdan Resolved olur. PUT /claims/{id}/admin-review
4
Uygunsuz İlanı Siler Şüpheli bir "buldum" ilanını tespit eder ve soft-delete yapar. DELETE /lost-items/{id}
